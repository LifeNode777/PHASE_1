## Module Folder Schema

Every module folder grows organically — GitHub creates a folder only when a
file lands in it — but always follows the same convention:

- `README.md` — module index: status, TRL, links to everything inside
- `SPEC.md` — goal, material stack, operational parameters
- `FALSIFICATION.md` — binary failure conditions ("the module fails if…")
- `LOG.md` — chronological journal: short dated entries (decision → link); never a storage place
- `docs/` — texts, drafts, article versions (`v0.1_…`, `v0.2_…`)
- `img/` — graphics, schematics, diagrams
- `sim/` — code, simulations, notebooks
- `data/` — raw measurements (appears with laboratory validation)

Artifacts live in their own folders. `LOG.md` only points to them.
The module `README.md` is the map, not the territory.
